Operators (decided 2026-05-29) need to move incidents in all directions to typo-correct mid-event, so we keep the permissive behavior rather than designing + enforcing a strict graph.

## B) UX feature gaps

### ✅ B1 – Stale-data banner 🔴 *(done 2026-05-28)*
`OperationsContext` now tracks `lastSyncAt`. New `<StaleDataBanner />` mounted in the root layout shows when WebSocket is disconnected/errored AND last successful operations load is >15s old. Pure visibility logic in `lib/stale-data.ts` (7 tests). Component test verifies hidden-when-connected, hidden-when-no-sync-yet, visible-when-stale, and re-disappear on reconnect.

### ✅ B2 – Incident status timeline 🔴 *(done 2026-05-28)*

Shipped v1: backend `GET /api/incidents/:id/timeline` endpoint joins `status_transitions` + `incident_assignments` (assign + unassign events) with bulk resource-name lookups (no N+1). Frontend `IncidentTimelinePopover` renders an (i) button in the operation-detail-modal header, anchored popover with compact log rows: `HH:MM:SS · icon · event · actor`. Static load on open; live updates deferred to v2.

**Original scope notes (preserved for reference):**
`StatusTransition` table is fully populated but never surfaced. Essential for debriefs and shift handovers.

**Scope (locked):**
- **Trigger**: small `(i)` button in the operation-detail-modal header, positioned right of the "Xh Y' seit Alarmierung" text. No tab, no dedicated page.
- **Reveal**: popover anchored to the `(i)` button; click outside to dismiss.
- **Events shown**: status transitions + assignments (crew/vehicle/material added or removed).
- **Visibility**: anyone who can see the incident (editor + viewer).
- **Liveness**: static load when the popover opens. WebSocket live-update deferred to v2.
- **Visual**: compact event log inside the popover – rows of `HH:MM:SS · Event · Actor`. Dense, scannable, matches the calm + dense design principle.

**Backend work**: new `GET /api/incidents/:id/timeline` endpoint joining `status_transitions` + `assignments`. No pagination needed for v1 (most incidents <50 events).

**Out of scope for this round:** Reko submission events, notification-sent events, audit_log entries (e.g. field edits). Add later if the v1 timeline feels too sparse.

### ⏭ B5 – Personnel qualification filtering (skipped)

### ✅ B6 – Resource double-book warning 🟡 *(done 2026-05-29)*
Client-only `Map<personId, {incidentId, removedAt}>` in operations-context, populated by `removeCrew` and queried by `assignPersonToOperation`. Inside a 5-minute window, re-binding a just-removed person to a *different* incident raises a warning toast ("Müller war vor 30s noch auf 'Bahnhof'") but still allows the assign. Same-incident re-bind (normal undo) doesn't warn. Pure tracker in `lib/recent-removals.ts` (9 tests). Cross-tab / cross-refresh deliberately out of scope – most cases are same-operator within seconds.

### ☐ B7 – Stats board with response-time metrics (future) 🟢
`stats.py` already computes `avg_duration_minutes` and similar – never displayed. Surface them on a dedicated **stats board** (not on individual cards). Future improvement.

### ☐ B8 – Offline status changes (large) 🟢
Drag-drop status change fails silently if network drops. No service worker, no local queue. Tablets at scene lose signal. Large scope (service worker + IndexedDB + mutation replay).

### ☐ B9 – Shift handover workflow (future) 🟢
Checkout is blocked while personnel are assigned (`crud/personnel_checkin.py:243`). **Not currently planned** – no shift changes today. Logged for future when shift rotations become operational.

### ✅ B10 – Enrich dispatch print slip 🟡 *(done 2026-05-27)*
Consolidated the two duplicate `_build_assignment_payload` functions into a single shared `crud/print_jobs.build_assignment_payload`. Manual prints (API) and auto-prints (on dispatch) now both include: Reko summary, internal notes, Nachbarhilfe note, zu_fuss flag, and per-vehicle driver + driver_stay info. Reko-tagged personnel are excluded from the crew list in both paths.

## C) Generalizability (multi-station)

### ☐ C1 – Wire i18n framework 🟢
No i18n today. ~500 hardcoded German strings across UI, print templates (`print-agent/formatters.py`), status enums, seed data. Install `next-intl`, extract strings, ship German first, add French/Italian later. Heavy lift; only justified if multi-region deployment becomes real.

### ☐ C2 – Multi-tenancy / Station model 🟢
No `Station`/tenant model. All data is global; auth has no station scoping. **Discuss with a real multi-station partner first** before implementing – operational doctrine and roster structure vary by canton and we shouldn't guess. Logged for that future conversation, not for immediate work.

### ☐ C3 – Configurable operational doctrine 🟢
Status enum (`models.py:277`) and vehicle taxonomy are hardcoded Swiss-German fire-service. Other cantons may have different workflows. Pairs with C2 – only worth tackling after partner-station validation.

## D) UI/UX efficiency

### ☐ D1 – Display board font scale (test with real screen first) 🟢
`app/display/board/page.tsx` uses `text-xs`/`text-sm` globally. May be unreadable from across a room. **Validate with an actual wall-mounted screen before resizing** – don't guess at sizes.

### ✅ D2 – Priority icon + label (not color-only) 🟡 *(done 2026-05-28)*
Display-board cards + the detail-modal title now use `AlertTriangle` / `AlertCircle` / `Info` plus an uppercase "Hoch/Mittel/Niedrig" label. Shared `priorityVisuals` table replaces the previously-duplicated color and label maps.

### ✅ D3 – Drag-drop error feedback 🔴 *(done 2026-05-28)*
Added status-failure branch in `operations-context.updateOperation` that calls `refreshOperations()` to snap the card back to server state and shows a clearer toast ("Status nicht geändert / Der Einsatz wurde auf den letzten Stand zurückgesetzt"). Other field updates keep the existing toast-only behavior – the field stays visible in the editor, no revert needed.

### ✅ D4 – Person double-booking visual surface 🔴 *(done 2026-05-28)*
`useDoubleBookedPersons` hook derives the set of names assigned to ≥2 incidents (5 tests). Sidebar `DraggablePerson` cards get a warning-bordered "Nx" badge with `AlertTriangle`. Affected crew badges on incident cards get warning-tinted styling with a leading `AlertTriangle`. Reko personnel intentionally excluded – they cycle through multiple incidents by design.

### ✅ D5 – Driver sidebar real-time sync 🔴 *(done 2026-05-28)*
Extracted a shared `useVehicleDrivers(eventId, enabled)` hook in `frontend/lib/hooks/use-vehicle-drivers.ts` that loads the driver map and subscribes to both the `special_function_update` WebSocket event and the `driver-assignment-changed` window event. Refactored 3 consumers – `SidePanelDetail`, `operation-detail-modal`, `mobile-incident-detail-sheet` – to use it. Sidebar + both detail surfaces now stay in sync without a manual refresh.

### ✅ D6 – Surface keyboard shortcuts in Cmd+K 🟡 *(verified done 2026-05-28)*
Command palette (`components/ui/command-palette.tsx`) already listens for both `Cmd+K` AND `?` (line 74) and every existing shortcut already appears with its key affordance beside the action. Nothing to ship.

### ✅ D7 – Unsaved-changes warning (pair with A3) 🟡 *(done 2026-05-28)*
Shipped as part of A3 via the shared `useUnsavedChangesWarning` hook + `UnsavedChangesDialog`. Hook installs a `beforeunload` listener while the form is dirty + open; close attempts go through `requestClose` which surfaces the confirm dialog. Tests in `use-unsaved-changes-warning.test.ts` (5 cases).

### ☐ D8 – Map keyboard navigation + a11y 🟢
`app/map/page.tsx`: no arrow-key pan, markers not tabbable, missing `role="region"` + `aria-label`. From `docs/UI_UX_FIXES.md#9`.

### ✅ D9 – Display status responsive grid 🟡 *(done 2026-05-27)*
Changed `app/display/status/page.tsx` to `grid-cols-2 md:grid-cols-3 xl:grid-cols-4`. Now adapts to tablets and narrower monitors.

### ✅ D10 – Reduce click depth for new incident + assign 🟡 *(verified done 2026-05-28)*
Plain `N` already opens the new-emergency modal (`page.tsx` keyboard handler – line 727 before extraction, now in `useKanbanShortcuts`). Hover quick-assign button already exists on each card. Both effectively done.

### ✅ D11 – Fix transfer button hover style 🟢 *(done 2026-05-27)*
Both transfer buttons switched from `variant="outline"` to `variant="ghost"` + `border border-border`. Removes the dark-mode `bg-input/50` hover that was reading as jarring blue, keeps a visible border for the button affordance.

### ✅ D12 – Operation detail modal auto-focus 🟢 *(done 2026-05-27)*
Added `autoFocus` to the Meldung textarea (not the LocationInput, which would have popped a geocoding popover). On tablet, the soft keyboard appears immediately when the modal opens.
